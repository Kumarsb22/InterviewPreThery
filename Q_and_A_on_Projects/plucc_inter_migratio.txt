✅ 20 Real-Time PUCC Project Migration Questions & Answers (3+ Years)

(Spring Boot Microservices + Angular + PostgreSQL + Migration)

🔹 1. Explain your PUCC project in short.

Answer:
PUCC (Pollution Under Control Certificate) is a government application used for registering pollution testing centers, verifying documents, approving centers, processing payments, and generating certificates.
My role was to migrate the legacy application built using JSP, Servlets, JDBC, and monolithic architecture into Spring Boot microservices with Angular frontend and PostgreSQL.

🔹 2. Why was the PUCC project migrated from JSP/Servlet to microservices?

Answer:

Old system was tightly coupled (difficult to enhance).

Performance issues due to single monolith.

Hard to scale for high traffic (state-wise users).

No API layer for integration.

Poor security, no JWT/OAuth.

Difficult to maintain code and deploy updates.

🔹 3. What were the main microservices created in the new PUCC system?

Answer:

Authentication Service (JWT)

PUCC Center Management Service

Document/Attachment Service

Payment Service

Notification Service

Certificate Generation Service

🔹 4. What challenges did you face while migrating JDBC code to Spring Data JPA?

Answer:

Converting handwritten SQL into entity relationships.

Handling custom joins and native queries.

Mapping DB tables with composite keys.

Eliminating duplicate DAO logic.

Ensuring ACID behavior with @Transactional.

🔹 5. How did you ensure backward compatibility while migrating?

Answer:

Maintained old API responses until Angular team completed UI changes.

Used feature flags for incremental rollout.

Created middleware adapters for old URL formats.

Released modules in phases: Auth → Document → Payment → Certificate.

🔹 6. Explain one major bug you fixed in the payment module during migration.

Answer:
Bug: Duplicate transactions were happening when users clicked multiple times.
Cause: Old application had no idempotency.
Fix: Implemented unique Request-ID and locked transaction processing.
Result: Duplicate payment reduced by 99%.

🔹 7. How did you migrate file upload (documents) from file system to microservice architecture?

Answer:

Created a Document Service with REST API for upload/download.

Stored files in file system / S3 / MinIO, metadata in PostgreSQL.

Implemented validations (size, type, virus scan).

Provided signed URLs for Angular UI.

🔹 8. How did you secure your microservices?

Answer:

Used Spring Security + JWT for all services.

Role-based authorization (Admin, Verifier, Center Owner).

API Gateway for central authentication.

Disabled CSRF for APIs.

Used HTTPS across services.

🔹 9. Explain the database changes during migration.

Answer:

Split monolithic DB into service-wise schemas.

Used Flyway for version-based migrations.

Normalized tables (removed redundant columns).

Added indexes for better performance (center_id, status).

🔹 10. How did you communicate between microservices?

Answer:

REST for synchronous communication.

RabbitMQ/Kafka for async communication (Notifications).

Feign Clients for internal API calls.

40% faster response time.

Cloud-ready microservices with independent scaling.

Easy deployment (Docker + CI/CD).

Better security and maintainability.

🔹 15. How did you convert Servlet session management to JWT?

Solution:

Removed HttpSession usage.

Used JWT token containing username + role.

Token validated at API Gateway.

No session stored at server (stateless).

Introduced routing guards for role-based screens.
